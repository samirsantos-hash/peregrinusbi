- Listing SWOT compares nullable metrics against other selected own-store listings only; keep external opportunities/threats unverified and never infer promotion returns or market rankings.

- Title v2 is a local editorial heuristic: fetch category limits via credential-free fixed public category URLs, keep unknown limits null, exclude length/estimated visual cut from scores, and never auto-write titles or activate AI.

- Listing-study topics compose existing account-scoped reads and capability guards; preserve store context across topic links, and never turn study weights into official ranking scores or position gains.

- Funnel impressions use paginated campaign-level Product Ads prints with explicit scope/coverage; never infer whole-store impressions or abandoned carts from visits, sales or order packs.

- Ads participation and TACOS may show explicitly labelled covered-date results independently; use each metric's matching revenue dates and expose coverage, never substitute partial values for full-period totals.
- Summary investment goals use metaInvestimentoAdsCoberta with same-date daily revenue; partial results must show coverage and suppress full-period comparisons and tier conclusions, preserving the strict full-period helper.

- Promotion results read paginated account-scoped opt-ins separately from historical performance; current participation never produces ROAS or ROI because sale attribution and realized costs are unconfirmed.
- Promotion participation lists use live per-item reads over the scanned active/paused catalog; incomplete coverage suspends outside-promotions classification, while distinct current opt-ins never imply stacked discounts or sale attribution.
- Per-listing promotion management reuses the existing preview/confirmation sheet; historical sales use exclusive paid-order buckets and never infer promotion identity from supplier offer IDs or current membership.
- Promotion-sale verification uses exact sale promotion ID/type; item advertising ROAS reads only exact external MLB groups and aligned daily sums, never family totals or promotion returns.

- Margin-based pricing is a client calculator using explicit per-item costs and charges, not markup; send resulting prices through the unchanged server preview/confirmation flow and never persist private cost inputs.

- The summary Quality Index averages saved official ML performance scores only for active scoped listings; show coverage and no prior comparison instead of invoking AI or substituting legacy health scores.
- Operational summary layout uses scoped `.resumo-sinergia` styles so presentation changes preserve same-date Ads calculations and monthly cancellation coverage rules.
- Summary funnel charts reuse nullable daily visits and paid orders from the same live summary; compare exact dates 30 days apart and compute revenue per visit from covered period totals, never impute missing visits or blend imports.
- Executive KPI sizing is scoped to `.resumo-executivo` with container-width tracks and natural row heights, so account-health content and Ads coverage notes cannot stretch every financial tile.
- Summary listing cancellations reuse the existing ABC query only with matching dates and confirmed order coverage; exclude ambiguous counts and never reconstruct listings from store totals.
